## Description

[Nest](https://github.com/nestjs/nest) framework TypeScript starter repository.

## Project setup

```bash
$ npm install
```

## HexaWave authentication setup

Copy `.env.example` to `.env` before starting the backend. Set
`HEXAWAVE_ADMIN_EMAIL` and a unique `HEXAWAVE_ADMIN_PASSWORD` (at least 12
characters) to bootstrap the administrator account; regular registration always
creates a user account and never grants admin access. Set
`HEXAWAVE_AUTH_SECRET` to a random value with at least 32 characters for
production. Local development generates a signing key in the ignored `data/`
directory when this variable is empty.

Registration and login use an HttpOnly session cookie. User credentials are
stored as salted scrypt hashes in `data/users.json`; project ownership is stored
in `data/project-owners.json`. This file-backed storage is intended for a
single local backend process only, not multi-instance production deployments.
Move these records to PostgreSQL and use shared durable session/key management
before deploying a multi-instance service.

## Google lead discovery setup

The CRM's Google lead discovery uses SerpApi. Create a key with SerpApi, set
`SERPAPI_API_KEY` in the private `backend/.env` file, and restart the backend.
Then refresh the CRM page; discovery and its optional daily schedule become
available when the backend reports the key is configured. Never add the key to
frontend environment variables or paste it into the browser. Provider usage may
be subject to SerpApi account limits and charges.

## Brevo CRM email sending

Install the backend dependencies with `npm install` from `backend/`, then set
`BREVO_SMTP_HOST`, `BREVO_SMTP_PORT`, `BREVO_SMTP_USER`, `BREVO_SMTP_KEY`, and
`BREVO_FROM_EMAIL` in the backend environment (for Render, set them on the
backend web service). Use the SMTP login and SMTP key from Brevo's transactional
email settings; the SMTP key is not the Brevo API key. `BREVO_FROM_NAME` is
optional. The sender address must be verified with Brevo.

After restarting the backend and refreshing the CRM, administrators can compose
and send an email to one lead at a time. Only leads in `READY_TO_CONTACT` or
`FOLLOW_UP` status are eligible; sending to a `READY_TO_CONTACT` lead changes
its status to `CONTACTED`. Suppressed, unsubscribed, bounced, invalid, and
other ineligible records cannot be emailed. `GET /api/email/cloudflare/status`
reports whether the SMTP settings are complete, and `POST /api/email/send`
performs an authenticated send. Keep SMTP credentials server-side and never add
them to frontend environment variables.

## Compile and run the project

```bash

$ npm run start:prod
```

```bash
$ npm run test:cov
```

## Deployment

When you're ready to deploy your NestJS application to production, there are some key steps you can take to ensure it runs as efficiently as possible. Check out the [deployment documentation](https://docs.nestjs.com/deployment) for more information.

If you are looking for a cloud-based platform to deploy your NestJS application, check out [Mau](https://mau.nestjs.com), our official platform for deploying NestJS applications on AWS. Mau makes deployment straightforward and fast, requiring just a few simple steps:

```bash
$ npm install -g @nestjs/mau
$ mau deploy
```

With Mau, you can deploy your application in just a few clicks, allowing you to focus on building features rather than managing infrastructure.

## Observability

In production applications, observability is essential for understanding how your system behaves, detecting issues early, and maintaining reliable performance.

[NestJS Observe](https://observe.nestjs.com) automatically instruments your NestJS application, giving you deep visibility into your system with minimal setup:

- **Distributed tracing:** Follow requests across services and understand how they flow through your system.
- **Waterfall analysis:** Visualize request execution and identify slow operations, bottlenecks, and unexpected delays.
- **Performance analysis:** Analyze application performance in real time and quickly pinpoint areas that need optimization.
- **Metrics:** Track key application and infrastructure metrics to understand system health and performance trends.
- **Logging:** Centralize and correlate logs with traces and other telemetry to make debugging easier.
- **Error tracking:** Detect errors quickly and investigate their root causes with the surrounding context.
- **SLA monitoring:** Track service-level objectives and identify when your application is approaching or exceeding defined thresholds.
- **Alarms and alerts:** Set up alerts for critical errors, performance degradation, SLA violations, and other anomalies so your team can react quickly.

This project is already instrumented. Create a free account at [observe.nestjs.com](https://observe.nestjs.com), add an application, and paste the generated app key and secret into the `ObserveModule.forRoot()` call in `src/app.module.ts`.

The free plan needs no payment details and covers 300,000 events a month. You can also browse the [live demo](https://www.observe-demo.nestjs.com/dashboard) first - the whole dashboard over a busy service's data, with nothing to install.
